ilo/closed-loop benchmark

8 runs · newest 2026-09-18 21:22:52
A model writes each task in each language, the program is run, and its error is fed back until it works — that repair loop is the “closed loop”. Measured per attempt-set, retries and repairs included: tokens, emitted characters, dollars and seconds. Program runtime is a different bench (bench/run.sh).
What the run names mean
warm cache
The provider's prefix cache is reused between repair turns, so repeated prompt prefixes bill at the cache rate. cold busts the cache on every attempt — an upper bound on input cost.
aligned
The spec sits in the system message and repairs append turns, so the cached prefix survives the retry. rewritten prompt is the older shape: each repair rewrites the prompt, which breaks the prefix on purpose.
curated / core / full spec
How much of ilo's own skill documentation the model was given in context. Comparators get their language's native agent-facing docs bundled instead.
What the numbers mean
output tokens
Everything the model emitted, reasoning included — across every attempt of the row, so retries, repairs and discarded drafts are in the count.
chars
Characters of the emitted program only — reasoning excluded — summed over every attempt, superseded drafts included. It cannot be divided by output tokens to get a density: those tokens are mostly reasoning, so the ratio measures thinking, not code.
retries
Attempts beyond the first, summed over the row's measurements — 0 is a row that worked first try. It is the clearest single number for how much repair work a language needed, and it drives the token, time and cost totals, all of which include the retries.
share
In the language table, this leg's slice of every token the tab moved — input + output across all legs. The bar under it splits that leg's own tokens into prompt and generated. The total row's −55% style cells are the other leg-versus-total view: how far the largest legs sit from the whole in that column, so a near-saturated column (prompt tokens) and a spread one (cost) read differently at a glance.
mix
The bar under the share figure: how much of that leg's tokens went to the prompt and how much the model generated. Both are measured, not inferred — input and output tokens as the provider billed them.
expects
The exact stdout a row must print to count as working. ↵ marks a line break; a row that runs but prints anything else is partial.
closed loop
The program is written, run, and its error fed back to the model, which rewrites it — repeated until it prints expects or the retry cap is reached. That feedback edge is the loop; an open-loop measure would count tokens to produce code it never ran.
time
Wall time of the whole attempt-set — every generation call plus every run of the program. It is not the program's own runtime (that is the wall-clock microbench in bench/run.sh).
input tokens
Prompt tokens sent to the provider across every attempt of the row (spec + task + repairs), before cache discounts.
total tokens
Input plus output, summed over every attempt: the whole provider-side volume a leg moved in this tab. It is a size, not a price — cache hits bill cheaper but count the same, so spend is the cost figure. Per row divides by task-rows, which makes it comparable across tabs with different task counts.
reps
Measurements averaged into a task-row. The comparator matrix measures the ilo arm once per comparator leg, so ilo rows show ×N.
working
Measurements (reps, not task-rows) whose program ran and printed the expected output within the retry cap. Cells read passed/taken — 6/8 — and the denominator is reps, because the comparator matrix measures the ilo arm once per comparator leg.
best
In a per-task table, the fewest output tokens among the languages that solved that task. It says who got there with the least emitted text, not who is fastest overall.
outcomes
In the language table, task-rows by outcome — one per row of the per-task tables. A row stands for all of its reps, so this is coarser than the rep-based working cell beside it: a row of 6 measurements that passed 5 reads as partial.
not measured
This language has no row on this task in this tab — the sweep has not run it yet, or it is absent from this run's legs. It is a gap in coverage, never a result.

Totals cover every task-row in this tab, every attempt inside it; per row means per single task attempt-set (one language, one task), so it is comparable across tabs with different task counts. share is this leg's slice of all the tokens the tab moved — the leg-versus-total view; the bar under it splits those tokens into prompt and generated.
